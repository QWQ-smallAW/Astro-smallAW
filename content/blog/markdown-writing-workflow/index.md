工具应该隐形。这套工作流的目标只有一个：打开编辑器，敲下正文，其他一切都自动发生。

## frontmatter 是最小元数据

每篇文章开头只有四个字段：

```yaml
---
title: 文章标题
description: 一两句话的摘要（列表页和 RSS 用）
date: 2026-09-01
tags: [写作, 工具]
---
```

`draft: true` 可以让文章在构建时被隐藏，适合写到一半的稿子。

## 标签的三个原则

1. **宁少勿多**：一篇文章最多三个标签
2. **可复用优先**：能归入已有标签就新建不建
3. **面向未来的自己**：标签是给一年后检索用的，不是给当下好看的

## 一个文件就是一个世界

不需要素材库、灵感清单、写作日历。所有未成型的想法都躺在 `content/blog/` 下的 `.md` 文件里，`draft: true` 就是它们的栖息地。写完就改字段，构建，发布。

```bash
$ echo "new post" > content/blog/$(date +%F)-new-post.md
$ npm run build && git push
```

写作的阻力每减少一分，输出的概率就多一分。
